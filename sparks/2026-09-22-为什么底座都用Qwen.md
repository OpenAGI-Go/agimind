# 为什么好多模型底座都是用 Qwen？

> **日期**：2026-09-22  
> **触发**：看 NanoJev（Qwen3-0.6B）和 Bespoke-Nimble-9B（Qwen3.5-9B）时冒出的问题  
> **性质**：随笔，不是论文结论

---

学 System One / Jev 开源复现时，很容易注意到一件事：NanoJev 用 Qwen3-0.6B，Nimble 用 Qwen3.5-9B。再往外看，很多可微调的小模型实验、决策头原型、本地部署 demo，底座也常是 Qwen。

这不是因为「System One 必须绑定 Qwen」，而是几件事叠在一起。

## 1. 许可和分发成本低

开源复现要做的不只是「能跑」，还要「能公开发」。  
底座许可若限制二次训练、商用或权重再分发，整个配方立刻变难。Qwen 系列对研究和多数商业场景相对友好，adapter、微调权重也好挂到 Hugging Face。做一天级开源实验的人，会优先避开许可麻烦。

## 2. 小模型已经够用

决策模型 / System One 风格任务，往往不需要写长文。  
真正要的是：给定状态和候选，吐出稳定分布。0.6B、9B 这种尺寸，若底座质量够，就能做出可看的原型。Qwen3 / 3.5 在同尺寸开源模型里经常够用，所以「小底座 + 决策头 / LoRA」成为默认组合。

## 3. 工具链成熟

实验时间大多花在数据、目标和评测上，不是重造 tokenizer。  
Qwen 在 Transformers、tokenizer、config、BF16、CUDA、LoRA 路径上成熟，`from_pretrained` 一条路走通。对要快速对照配方的人，这比「 theoretically 更合适但生态稀疏」的底座更有吸引力。

## 4. 中英文和指令跟随都还行

状态文本、选项描述、boolean / choice / score 指令，都依赖底座听懂题面。  
Qwen 在中英文和指令跟随上通常够稳；中文社区熟悉度也高，文档、踩坑记录、二次开发多。路径依赖一旦形成，后来者对照实验也倾向同一底座，好把差异归因到配方，而不是底座。

## 5. 硬件现实

单卡 A800 / H100 上，微调 0.6B–9B 现实；27B+ 全参或闭源 API 蒸馏，成本和门槛都更高。  
开源复现天然偏向「能本地跑完训练、能公开放权重」的底座。Qwen 正好卡在这个区间。

## 6. 社区路径依赖

前几个公开的 Jev 风格复现用了 Qwen 之后，后来者会跟着走：  
同一底座上比数据、比读出方式、比评测协议，比换底座更干净。于是「好多模型都用 Qwen」看起来像共识，其实有一半是复现实验的对照便利。

---

## 一句话

大家选 Qwen，多半是因为它在**开放许可、小模型性价比、工具链完整、本地可训**上最适合做快速开源实验；不是因为决策模型或 System One 在原理上属于 Qwen。

换底座当然可以，但那时要多付一层成本：许可、tokenizer、训练稳定性、以及「别人没法直接对照你的配方」。

## 对自己的提醒

以后再看到「又一个 Qwen 底座」时，先问：

1. 它是在借用底座能力，还是在验证一个与底座无关的新配方？  
2. 如果换 Llama / Gemma / 自家底座，结论还成立吗？  
3. 评测比的是配方差异，还是底座差异？

把这三问问清楚，就不容易把「生态选择」误读成「架构必然」。
