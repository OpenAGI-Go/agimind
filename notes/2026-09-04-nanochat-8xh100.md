### 1.3 如果用 H20（国内默认选项）

**能跑。** H20 是同一代 Hopper（SM 90），FP8 / bf16 / FlashAttention 3 / `torch._scaled_mm` 都在。`speedrun.sh` 不用换配方，软件栈也不用换。换的是**时间预期和成功标准**。

H20 是给中国市场砍过算力的 H100：显存和带宽留下了（推理友好），矩阵算力按出口管制压到大约 **1/7**。nanochat 这条 d24 预训练是算力墙，不是显存墙，所以会几乎按算力比变慢。

| | 8×H100 SXM（官方） | 8×H20 96GB（国内常见） |
| --- | --- | --- |
| 架构 | Hopper SM 90 | 同左 |
| 单卡显存 | 80GB HBM3 | **96GB HBM3** |
| 显存带宽 | ~3.35 TB/s | **~4.0 TB/s**（还略快） |
| BF16 Tensor（稠密） | ~989 TFLOPS | **~148 TFLOPS**（约 15%） |
| FP8 Tensor（稠密） | ~1979 TFLOPS | **~296 TFLOPS**（约 15%） |
| NVLink | 900 GB/s 级 | 通常保留；确认 `topo -m` |
| TDP | SXM 最高 ~700W | ~400W |
| `--fp8` | 开 | **同样开**（有 FP8 tensor core） |
| 官方 speedrun 墙钟 | ~1.5h | **粗估 10–12h**（1.5 × ~7，再加评测） |
| 对 leaderboard | 可以直接比墙钟 | **不要比墙钟**；只比 val_bpb / CORE |
| 显存策略 | d24 常用 `bs=16`（32 易 OOM） | 先试 **`--device-batch-size=32`**，OOM 再退回 16 |

Roofline 一句话：H100 要 ~590 FLOP/byte 才坐满算力屋顶；H20 大约 ~74 FLOP/byte 就坐满。LLM 预训练 GEMM 远高于这个，所以 **两边都是算力受限**，H20 只是屋顶矮很多。96GB 多出来的显存几乎帮不上墙钟，只让你少做一次 gradient accumulation。

**命令（H20 建议，相对 `speedrun.sh` 只改 batch）：**

```bash
# tokenizer / 数据 / SFT / eval 仍走 speedrun.sh 原样
# 只把预训练那一行换成：
torchrun --standalone --nproc_per_node=8 -m scripts.base_train -- \
  --depth=24 \
  --target-param-data-ratio=8 \
  --device-batch-size=32 \
  --fp8 \
  --run=$WANDB_RUN
```

`bs=32` 若 OOM，改回 16，不要先改 `--depth`。

**MFU 会显示 0%。** `nanochat/common.py` 的 `get_peak_flops()` 表里有 H100 / H800 / H200，**没有 H20**，未知卡返回 `inf`。上机后在表里加一行，否则日志里的 MFU 没意义：

```python
(["h20"], 148e12),   # BF16 dense peak；放在 h100 条目附近
```

带宽表同样没有 H20，需要的话加 `(["h20"], 4.0e12)`。这是记数用的补丁，不是训练正确性补丁。

**费用：** 国内 8×H20 时租通常低于 8×H100，但要乘 7 倍墙钟。先问清楚卡时价，再决定是过夜一次跑完，还是先用 `depth=12` 做 20 分钟冒烟。不要按官方 \$48 去套。

**不要用 H20 做的事：** 拿 `total_training_time` 去对 Time-to-GPT-2 榜。那条榜写死了 8×H100。我们的成功标准是：CORE > 0.256525，并且能用 `chat_cli` 对话。

## 3. 这条配方在训什么

`speedrun.sh` 当前（`92d63d4`）预训练命令：

```bash
torchrun --standalone --nproc_per_node=8 -m scripts.base_train -- \
  --depth=24 \
  --target-param-data-ratio=8 \
  --device-batch-size=16 \
  --fp8 \
  --run=$WANDB_RUN
```

| 旋钮 | 取值 | 含义 |
| --- | --- | --- |
| `--depth` | 24 | 唯一复杂度拨盘；宽、头数、训练长度都从它推 |
| 模型宽度 | `depth × 64` 再对齐到 `head_dim=128` | d24 → dim 1536，12 head |
| `--max-seq-len` | 2048（默认） | |
| `--device-batch-size` | 16 | 理想是 32（16×2048×8=262144，需 grad accum 凑满 ~524288 tokens） |
| `--fp8` | 开 | H100 tensor core；没有 FP8 就去掉，改 bf16 |
| `--target-param-data-ratio` | 8 | 略欠训（compute-optimal 默认偏 10.5–12），为了在更短时间内摸到 GPT-2 CORE |
| 数据 | NVIDIA ClimbMix | tokenizer 用前 8 shard（~2B 字符）；预训练后台拉到 170 shard |
| tokenizer vocab | 32768（2^15） | |

官方 leaderboard（8×H100，CORE 超过 0.256525 的墙钟；数字会随 master 变）：

| # | 墙钟 | val_bpb | CORE | 备注 |
| --- | --- | --- | --- | --- |
| GPT-2 原版 | 168h（2019） | — | 0.2565 | 对照基线 |
| 现配方量级 | ~1.5–2h | ~0.72 | ≥0.256 | 我们要对的标尺 |
| 榜上较好记录 | 1.65h | 0.718 | 0.2626 | 2026-03，commit `a825e63` |

我们这一跑先求 **能复现、能对话**，不求刷榜。

## 6. 失败与踩坑

| 时间 | 阶段 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- | --- |
| | | | | |

常见坑（还没踩，先备着）：

- 显存不够：降 `--device-batch-size`，不要先改 depth。H20 则先升到 32。  
- 不是 Hopper 却开了 `--fp8`（A100 / 4090）：删掉该 flag。H20 不要删。  
- H20 上 MFU=0%：`get_peak_flops` 缺条目，不是没在算。  
- `uv sync --extra gpu` 装到 CPU 版 torch：看 `torch.cuda.device_count()`。  
- 数据没下完就训：`speedrun.sh` 里有 `wait $DATASET_DOWNLOAD_PID`，手跑时不要跳过。  
- SFT 第一次极慢：在拉 HF 数据集，看磁盘而不是 GPU。  
- 对话找不到权重：确认 `NANOCHAT_BASE_DIR` 和 `chatsft_checkpoints/`。
